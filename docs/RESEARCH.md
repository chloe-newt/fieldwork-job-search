# Source and architecture research

Reviewed 21 September 2026, before implementation. The original implementation was developed independently. The later employer catalogue adapts third-party data with MIT attribution; see the follow-up below.

| Primary source | Findings and architectural decision |
|---|---|
| [SpeedyApply JobSpy](https://github.com/speedyapply/JobSpy) and [repository activity](https://github.com/speedyapply) | Broad scraper coverage, but upkeep and platform constraints are unavoidable. Organisation listing reported its latest update on 18 February 2026. Useful common-schema precedent; not adopted as a core dependency or a claim of authorised platform access. |
| [Job Tracker](https://github.com/Muatasim-Aswad/job-tracker) | Active project with a persistent opportunity record and multiple source URLs. Adopted that data-model approach, while implementing native Windows operation and deterministic assessment independently. Its documented native-Windows limitation makes it an unsuitable base here. |
| [JobSync](https://github.com/Gsync/jobsync) | Useful tracker/export/self-hosting patterns. Avoided making its optional intelligence or remote services part of the local core. |
| [ApplyPack](https://github.com/applypack/applypack) | Useful distinction between tracked employer boards and aggregator discovery; health/failure visibility and persistent state are valuable. Did not adopt its AI backends, Postgres or subscription-dependent classification. |
| [Greenhouse Job Board API](https://docs.greenhouse.io/job-board.html) | Public job-board GET endpoints expose structured descriptions and employer application routes without authentication. Implemented board-token adapter. Isomorphic Labs verified live. |
| [Official Lever postings API](https://github.com/lever/postings-api) | Public published postings, pagination, location/work-pattern fields and application URLs. Implemented GET-only adapter; application submission API is not used. Veeva verified live. |
| [SmartRecruiters endpoints](https://developers.smartrecruiters.com/docs/endpoints) | Paginated company postings plus per-posting detail. Implemented bounded UK discovery; authentication/access failure is visible. LGC public endpoints verified live. |
| [Workday API overview](https://developer.workday.com/api-overview) | Official APIs generally assume tenant integration access. An undocumented careers-site endpoint is not treated as a guaranteed public cross-employer API. Supported routes here are feeds, authorised JSON-LD pages, indexed links and manual advert import. |
| [NHS Jobs integration guidance](https://www.nhsbsa.nhs.uk/cy/node/11608) | Official self-serve XML/RSS advert feeds; the current linked specification is v1.07, May 2026. Implemented `https://www.jobs.nhs.uk/api/v1/search_xml` with keyword, location, pagination and external-only filtering. Truncated descriptions are enriched from public advert pages. Verified UKHSA employer code K9919. |
| [jobs.ac.uk terms](https://www.jobs.ac.uk/legal/terms-and-conditions) and [robots.txt](https://www.jobs.ac.uk/robots.txt) | Personal downloading is described in publisher terms. Old RSS URLs tested did not work reliably. Implemented bounded personal-use search-page links plus JobPosting metadata; no republishing service. It respects robots exclusions and records parser/HTTP failures. |
| [Civil Service Jobs](https://www.civilservicejobs.service.gov.uk/csr/index.cgi) | Returned HTTP 200 containing “Quick Check Needed” / CAPTCHA. This is a blocked automated search, not successful discovery. Included explicit manual strategy, government search links, optional indexed discovery and a separate UKHSA NHS mirror. No challenge circumvention. |
| [TfL Unified API](https://tfl.gov.uk/info-for/open-data-users/unified-api) and [journey API guide](https://content.tfl.gov.uk/journey-planner-api-documentation.pdf) | Use public transport routing and persist provenance/cache. Verified coordinate-based journey endpoint; the guessed mode `publictransport` was rejected, so final code supplies supported transport modes. No straight-line travel times. |

The standalone requirement drives the architecture: native Node.js 24, native SQLite, local browser assets, private runtime copy, standalone Windows launcher and ordinary Windows Task Scheduler. No ChatGPT memory, MCP connector, developer tooling, cloud hosting or OpenAI call is on the operating path.

Source coverage is intentionally transparent. LinkedIn and Indeed browser searches and copied advert imports work without API keys; automatic scraping is not enabled. Browser links are not counted as source checks. A future source addition must document its access route, terms and schema rather than merely list a board name as “supported”.

## Supplied AI Job Search follow-up

Inspected the user-supplied `job-search-master.zip` as source material, without executing its skills, scripts or agent configuration. Its README identifies MadsLorentzen/ai-job-search and its MIT licence credits Mads Lorentzen (2026). The employer board catalogue is adapted with the licence retained in [THIRD_PARTY_NOTICES.md](../THIRD_PARTY_NOTICES.md). The DeepMind board from that archive returned HTTP 404 during validation and was omitted.

The [official Ashby posting API documentation](https://developers.ashbyhq.com/docs/public-job-posting-api) informed the native connector, including secondary locations, listed/unlisted status, work pattern and compensation. The documentation describes `publishedAt` as last published, so it is not represented as first posted.

[Indeed’s terms](https://www.indeed.com/legal) prohibit automated systems from accessing the site, in bulk or otherwise, without written permission except permitted robots crawling. A low request count is not an authorisation. Fieldwork adds a user-driven browser-search/pasted-advert workflow and local job-key deduplication. The archive’s Indeed scraper is not incorporated. No rate-limit, CAPTCHA, fingerprint or account-control circumvention is implemented.
